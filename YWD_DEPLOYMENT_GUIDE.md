# YwD — Production Deployment & DevOps Runbook

**Target Cloud Provider:** Vercel (Edge & Serverless Node.js Runtime)  
**Database Provider:** Neon Serverless PostgreSQL (AWS `us-east-2`)  
**Media Storage:** Cloudinary  
**Payment Gateway:** Razorpay India  
**Transactional Communications:** Resend  

---

## 2. Database Migration & Seeding Procedure

When deploying to a new database environment, execute the following steps:

### Step 1: Generate Prisma Client
```bash
npx prisma generate
```

### Step 2: Push Relational Schema to Neon
```bash
npx prisma db push
```

### Step 3: Run Full Catalog Seeding
To populate the categories, subcategories, genuine student products, and standard demo accounts:
```bash
node prisma/seed.js
```

### Step 4: Provision Secure Administrator Credentials
Never use default or hardcoded passwords for administrator accounts. Use the dedicated CLI provisioning tool:
```bash
# Provision or rotate administrator account
node scripts/provision-admin.js admin@ywd.in "YourSecurePasswordOrLeaveEmptyForAutoGenerated"
```

### Step 5: Verify Database Health & Persistence
Run the independent database verification test:
```bash
node scripts/audit-db.js
node verify-neon-persistence.js
```

## 3. Vercel Build Configuration

In `vercel.json` or project settings:
- **Build Command:** `next build`
- **Install Command:** `npm install`
- **Output Directory:** `.next`
- **Node.js Version:** `20.x` or `22.x`

### Production Serverless Hygiene
- The Prisma client instance is cached on `globalThis` to prevent connection exhaustion in serverless lambdas.
- Connection pool limits are set to `max: 10` with `idleTimeoutMillis: 30000` to prevent saturating Neon connection limits.
- IPv4 DNS resolution is enforced in `src/lib/prisma.ts` to prevent dual-stack latency penalties.

## 4. Post-Deployment Verification Checklist

1. [ ] **Homepage & Catalog:** Verify that `https://ywd-topaz.vercel.app/` loads authentic products from PostgreSQL with zero fallback banners.
2. [ ] **Filtering & Search:** Test category filtering ("Electronics", "Academic", "College Essentials") and full-text search.
3. [ ] **Student Registration:** Register a new test student account (`student.test@campus.edu`) and confirm successful sign-in.
4. [ ] **Admin Console:** Navigate to `/admin` and authenticate using credentials provisioned via `node scripts/provision-admin.js`. Verify metrics, catalog items, bookings, and audit logs display correctly. Confirm that non-admin and demo accounts are blocked.
5. [ ] **Rental Booking:** Test date selection and rental checkout; verify that collision prevention blocks double bookings.
6. [ ] **OTP Handover:** Test pickup verification with the 6-digit OTP code in `/dashboard`.
